# 公开发布与隐私边界

## 发布原则

本仓库以独立的新工程发布，只包含 `release-manifest.json` 列出的文本文件。没有导入开发环境配置仓库或其 Git 历史。

不包含：

- API 凭据、私钥、登录令牌、Cookie、订阅与付款资料；
- 个人姓名、联系方式、机器名或真实用户目录；
- 私有域名、服务端点、IP、端口、代理配置和部署地址；
- 主模型或子模型的私人配置、服务商账户与订阅；
- 原始会话、消息标识、截图、论文、译文、Word/PDF 等二进制产物；
- 从环境变量或本机配置导出的认证信息。

保留的外部链接仅限公开的 OpenCode 官方文档、公开上游项目与本公开仓库；它们不是用户服务地址。MIT 使用通用项目贡献者署名。

## 防护层

1. 文件白名单，拒绝额外文件、符号链接和二进制内容。
2. 格式、内容、相对路径、敏感模式和外部 URL 白名单检查。
3. 检查实际暂存文件与提交内容，而非只看工作目录。
4. 独立人工复核；私有风险词只在本地内存中比对，不写入公开扫描规则。
5. 提交采用通用作者身份，不继承开发者 Git 姓名或邮箱。
6. 只推送预期分支，不使用镜像推送、不附带本地日志或历史。

## 扫描器的限制

扫描器能识别部分典型密钥、地址和个人路径模式，不能证明任何文本都绝对没有隐私。不认识的秘密格式、无明显特征的个人资料和未来新增内容仍需人工检查。

检查输出只报告文件、行号与问题类型，不回显疑似秘密。若发现泄露，应停止推送；已公开的凭据应撤销或轮换，不能只依赖删除文件。

CI 运行工作目录和索引两种检查。通用提交作者、分支选择与历史处理仍属于发布者必须人工确认的流程，不由扫描器强制执行。

## Git 历史与缓存

替换可达分支历史可以避免新的发布分支继续携带旧作者元数据，但不能保证托管平台、缓存或他人副本清除曾经公开的信息。需要时由仓库所有者按平台流程处理；不要在 issue 中粘贴待删除的个人内容。

后续贡献不要附原始诊断包。用合成示例、相对路径和匿名字段复现问题，不上传完整运行环境。
