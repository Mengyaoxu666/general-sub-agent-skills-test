# 开发设计

## 目标

降低主模型累计处理的 Token，同时保留合格交付和明确的任务验收节点。这里不以子 Agent 的 Token 为优化指标，也不把它当成免费资源。

这是行为提示词，不是调度器插件、计费器或权限系统。调用是否成功、模型如何选择和文件能否写入，由具体运行环境决定。

## 从旧设计到当前设计

早期设计只允许子 Agent 执行机械辅助步骤，主模型仍要读取多数材料、融合正文并重复验证。额外的加载、委派、摘录和复核轮次可能让主模型用量反而上升。

当前设计把完整的、可验收的任务交给执行者，包括分析、撰写、编码、文件生成和验证。主模型保留目标、关键裁决、逐任务验收和最终把关，不亲自再做同一份全文工作。

## 任务边界

适合的边界是“读完指定材料并形成证据报告”“实现一个功能并通过相关测试”“完成一份文档”，而不是“调用一次搜索工具”。

执行流示例：

1. 主 Agent 分派阅读分析任务。
2. general 读取原文、分析、保存完整报告，返回回执。
3. 主 Agent 根据验收条件检查回执与必要证据，决定通过或纠错。
4. 通过后推进依赖任务；无依赖任务可并行。
5. 需要完整复核时，另一位 general 检查输入与产物并保存检查单。
6. 主 Agent 处理分歧并交付产物路径。

每项任务必须回报；内部连续工具调用无需逐步中转。回执不是完整报告的复制，而是状态、路径、结论、实际验证结果和待决定问题。建议 200 字不是隐藏重要失败的理由。

## 质量责任

复核可以委派，责任不能转移。主模型仍需审视证据强度、处理冲突，在异常位置局部查看原始材料；不能只凭执行者自称成功而通过。

反过来，逐任务验收也不要求主模型把所有原文、代码和完整报告重新读一遍。应在任务开始就定义能够检查的完成标准。

## 运行条件

本工程不提供主模型或子模型配置。使用者需要已有的 general/explore Agent 和相应权限；未指定子模型时可能继承主模型。若环境没有这些 Agent，需先完成配置，不应伪称已委派。

领域技能在实际执行阅读或工程操作的 Agent 中加载。本工程不依赖开发者的全局 AGENTS 文件，也不自带文献、工程设计或账户信息。

## 文件交接的代价

文件交接减少正文反复进入主模型上下文，但不是零开销。过短回执可能丢失重要限制，过细分工可能增加轮次，过量主模型局部复核也会累积用量。短任务不必强行委派。

## 贡献与发布

修改核心规则时同步检查命令、README 和回归测试。新增文件先加入发布白名单，再进行独立人工复核。真实实验记录在本地保留；对外只发布匿名摘要与合成示例。

用量脚本仅汇总传入的匿名 JSON，不连接任何模型或服务，不访问环境变量中的认证信息。
