# 验证说明与匿名实验摘要

## 必须区分的结论

1. **加载成功**：Skill 正文确实被工具加载。
2. **执行成功**：真实子 Agent 完成任务并交回产物。
3. **交付合格**：产物经过独立质量检查。
4. **完整降耗证明**：同任务的全部主模型用量可核验，且比较口径一致。

前三项成立，不会自动证明第四项。

## 已有真实案例的匿名摘要

历史上对一个多步骤文档任务各执行一次直接处理和当前调度流程，两组使用相同主模型、源材料、机械工具和交付要求。此处不发布论文身份、作者、文件路径、模型或服务商标识、会话或消息标识及原始日志。

| 主模型归一化字段 | 直接处理 | 调度流程 |
| --- | ---: | ---: |
| input | 332,175 | 566,530 |
| output | 48,799 | 15,887 |
| reasoning | 12,841 | 9,868 |
| cache.read | 5,417,088 | 2,600,192 |
| cache.write | 0 | 0 |
| 已记录合计 | 5,810,903 | 3,192,477 |
| 缺失用量的响应数 | 0 | 1 |

已记录合计低约 **45.1%**，但调度侧有一条中断响应缺失用量。**准确节省率未知，不能把缺失值当成零。** 在基线完整、缺失量非负的前提下，45.1% 只是该口径的最大可能降幅，不是已证明的节省率，更不是可以保证的最低降幅。未缓存 input 反而增加约 70.6%，也不能将上述比例等同账单节省。

两组均完成要求的产物并达到独立质量检查的最低门槛；调度组仍有非阻断编辑问题。工作流中发生过权限匹配、命令卡住和回执恢复，因此无人干预稳定性未通过。准备、开发、控制器与独立质量检查不属于这两个受测主会话。

更早的一次短文件任务中，旧版委派流程的主模型字段合计增加约 62.8%，所有模型合计增加约 91.0%。这也是改成“子 Agent 负责实质执行、文件交接、短回执”的动机，而非应当隐藏的反例。

本公开摘要保留负面结果与计量限制，但出于隐私不发布原始日志，外部读者无法据此重新审计历史调用。它不是可复现实验数据集，也不是统计显著性或普遍性能保证。

## 如何自行验证

- 在独立会话执行相同任务，固定主模型、输入、工具、质量要求与统计边界。
- 基线由主模型直接完成，调度侧通过 `/dispatch` 执行。
- 主模型的每次响应都计入，包括加载、返工、恢复和最终交付；不要只看最后一次响应。
- 先通过产物完整性和独立质量门槛，再讨论用量；未完成组不能与完成组比节省率。
- 单独报告输入、输出、推理、缓存读写。适配器对字段的定义可能不同，不要盲目把重叠字段相加。
- 缺失用量标为未知，不补估算当实测；保留失败记录，不挑选更好看的中途数字。
- 用户若只关心主模型，应明确不计子 Agent；若关心总账单，必须另行取得完整价格与所有模型用量。

## 离线工具

`scripts/summarize_usage.py` 只处理 [合成匿名示例](../examples/usage-summary.json)，不读取会话服务：

```text
python -B scripts/summarize_usage.py examples/usage-summary.json
```

格式只接受匿名实验分组和 Token 字段，不接受路径、端点、模型标识、账户或会话日志。`children` 只用于表明有子任务，其用量不计入主模型指标。输入拒绝额外字段；缺失计数会使精确节省率保持为空。

本工具是字段汇总器，不能核验模型是否真的调用、产物是否合格或输入是否伪造。那些仍需要运行环境中的独立证据。
